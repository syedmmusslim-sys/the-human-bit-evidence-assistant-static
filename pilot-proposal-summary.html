Pilot proposal · non-case pilot collateral

Closeable concierge paid-pilot proposal

A single-page proposal a CAS lead can send internally to approve one governed close cycle. This page is deliberately non-case pilot collateral; the Kainga case proof remains in the demo, handoff and packet. All pricing and ROI figures are labelled hypothesis/synthetic until measured in the pilot.

Static walkthrough, not the app. No mutable API, no real client data, and no hosted-service claim. This proposal is a scoping document and order-form skeleton, not a signed contract.

Ideal customer profile (ICP) and qualification criteria

Ideal customer profile

A bookkeeping/accounting/CAS firm running recurring monthly or quarterly close for multiple clients, with a named reviewer separate from the staff who chase evidence.

Qualification criteria

  • Has a recurring, describable close blocker (missing or wrong client evidence).
  • Can name a sponsor, a reviewer, and a staff operator.
  • Can supply synthetic, redacted, or separately governed sample data.
  • Has a baseline it is willing to measure against.

Scope and exclusions

In scope

  • One close cycle for 1–3 pilot clients.
  • Facilitated setup and workflow mapping on governed/synthetic data.
  • Reviewer-gated evidence workflow, chase drafting with approval, and a manager handoff packet.
  • Baseline capture and an end-of-pilot report.

Explicit exclusions

  • Production hosting, durable mutable public URLs, or live integrations.
  • Real-client-data handling unless separately governed by the buyer.
  • Tax, legal, or audit advice.
  • Any signed or tamper-proof export claim.

Buyer inputs and responsibilities

  • Named sponsor, reviewer, and staff operator, committed for the cycle.
  • One agreed close blocker and a governed/synthetic data set.
  • A measurable baseline for the success metrics below.
  • A 30-minute end-of-pilot go/no-go review.

Deliverables

Workflow setup

Configured close-readiness workflow for the agreed blocker on governed data.

Manager handoff packet

Decision summary, evidence status, chase history, audit scope, and manager questions.

End-of-pilot report

Measured metric movement against baseline plus a go/no-go recommendation.

Weekly cadence

  • Week 0: kickoff, roles, data boundary, and baseline capture.
  • Week 1: run the close-readiness workflow; mid-week check-in.
  • Week 2: manager handoff review, scorecard, and go/no-go.

Fee / range hypothesis

Fee hypothesis: a scoped concierge paid-pilot in the AUD $2,000–$5,000 range for one close cycle. This is a hypothesis, not a quote or a guarantee, and is confirmed in writing before any work begins.

Pilot order-form skeleton

  • Buyer legal name: to complete before kickoff.
  • Sponsor / reviewer / staff operator: named before day 0.
  • Pilot fee: AUD $2,000–$5,000 fixed-fee range, confirmed in writing before work starts.
  • Payment terms: invoice on kickoff unless procurement requires written variation.
  • Scope: one close cycle, 1–3 clients, one agreed close-readiness blocker.
  • Acceptance criteria: baseline captured; governed/synthetic workflow run; manager handoff reviewed; end-of-pilot report delivered; go/no-go decision recorded.
  • Liability / advice boundary: no tax, legal, audit, assurance, or production controls advice.
  • IP/confidentiality: buyer retains client materials; Evidence Assistant retains product/workflow IP; confidential data must stay synthetic, redacted, or separately governed.
  • Post-pilot conversion: separate SOW required for any hosted, integrated, real-client-data, or production deployment.

Cancellation / stop rule

Either side may stop the pilot if the data boundary cannot be maintained, the roles are not staffed, or the first handoff review shows no reduction in review effort. On stop, only work completed to date is billable within the agreed range.

Security / data boundary

  • Read-only static artifact; no mutable API, no forms, and no server calls from this static artifact.
  • Synthetic, redacted, or separately governed data only for the pilot.
  • Static public proof is allowed only when byte/hash/header verification passes; no durable production hosting, mutable SaaS, or real-client-data claim.
  • Human approval before any send; nothing auto-sends.

Procurement-safe boundary

We can discuss a governed concierge pilot now. We cannot sign for production SaaS, real-client-data hosting, live integrations, signed/tamper-proof exports, or promised financial return until those controls are built and reviewed. A real DPA/security appendix remains a launch blocker, not a completed artifact.
