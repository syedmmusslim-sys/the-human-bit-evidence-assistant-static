Public verifier pack · downloadable proof instructions

Download and run the export-integrity verifier locally.

Build 36 turns the export-integrity story into an executable buyer proof: a downloadable verifier, a README, the expected pass/fail signal, and a clear non-production-signing boundary.

The verifier proves only that a local/static export bundle matches its tamper-evident demo seal. It does not upload files, approve evidence, send email, notarise records, or make this static artifact mutable SaaS.

Downloadable verifier files

export-bundle-verifier.mjs

The Node.js verifier copied into the public static artifact. It checks export-integrity-signature.json, signed file byte counts, SHA-256 hashes, payload hash, public key parse, and Ed25519 signature verification.

VERIFIER-PACK-README.md

Step-by-step local instructions for where to place the verifier, how to run it, what a pass looks like, and what tamper failure looks like.

Run command

node export-bundle-verifier.mjs build36-export-bundle

Expected success signal:

EXPORT_INTEGRITY_PASS build-36 10 files

If any signed file changes after export, the verifier emits EXPORT_INTEGRITY_FAIL and exits non-zero.

What this proves

Proves

  • The export bundle still matches the generated export-integrity-signature.json.
  • Signed file byte counts and SHA-256 hashes match.
  • The signed payload hash and Ed25519 signature verify.
  • Tampered export files fail verification.

Does not prove

  • No production identity signing, legal-grade non-repudiation, key custody, timestamping, or notarisation.
  • No tenant auth, storage, integrations, live upload/reply/review workflow, or real-client-data approval.
  • No AI auto-acceptance and no auto-send of real emails.
