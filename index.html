Static walkthrough, not the app

Watch the case change state: blocked → received → reviewed → chased → handed off.

Evidence Assistant is a reviewer-ready close-readiness workflow for bookkeeping, accounting, and CAS teams. This is a static state-transition product demo: each beat shows the current state, one dominant action, what is blocked, and exactly what changes in the case — from “we cannot close” through evidence intake, reviewer decision, and chase, to a manager handoff without chasing the wrong things.

→

After

Current boundary: this is a static walkthrough, not the app. It has no mutable API, no forms, no server calls, no real client data, and no claim that the local-only build can safely hold client files or run as a hosted service.

Operating roles in this demo

Partner/CAS lead

Decides whether to approve a one-cycle pilot based on handoff quality, risk boundary, and staff time saved.

Reviewer

The only role that can accept or reject evidence. Their decision controls packet inclusion and chase exclusions.

Staff operator

Chases unresolved blockers only; never chases accepted items or items paused for reviewer decision.

Client-facing operator

Uses approved chase copy only after staff approval; this static kit never auto-sends and never collects documents.

4 Current state: Chase approval

Chase approval

What staff sees

The chase draft includes only the missing payroll, the corrected August bank statement, and a readable supplier invoice.

Dominant action (one)

Staff reviews and approves a simulated send that names the exact client action.

What is blocked / disabled

No auto-send. Accepted items cannot be added to the chase. Waiting-review items stay paused. Send is disabled until staff approval.

Before

A reply-all chases everything, including the already-accepted invoices.

→

What changes in the case (after)

The chase asks only for what still blocks close, after human approval.

Packet handoff

What staff sees

The packet gathers accepted evidence, explicit unresolved blockers, chase history, audit scope, and manager questions.

Dominant action (one)

Hand off the packet to the manager.

What is blocked / disabled

The packet cannot silently record unresolved or waiting-review items as done.

Before

A folder of files; the manager reconstructs the story.

→

What changes in the case (after)

A decision trail that explains why the close is, or is not, ready.

packet-ready

What changes in the case: accepted evidence plus explicit unresolved blockers, chase history, audit scope, manager questions, and local deterministic proof are assembled for handoff.

Same messy synthetic email: where generic AI and spreadsheets fail

Same messy synthetic email: “Here are the July bank statement, some August contractor invoices, payroll later, and a blurry supplier photo. Also I found the credit card statement.” Generic AI can draft a plausible chase note and summary from it, but it does not own workflow state — so the same input can produce the failures below.

Generic AI can draft plausible prose

Given pasted emails and a checklist, generic AI can draft a chase note and a summary. It may also chase already-accepted contractor invoices or treat a July bank statement as enough for August when the prompt loses context.

Evidence Assistant preserves workflow state

The Evidence Assistant state result blocks each failure mode: accepted evidence is not chased, waiting-review is held, wrong-period evidence is blocked from the packet, and a non-reviewer cannot accept. Only reviewer decisions move evidence into the packet.
